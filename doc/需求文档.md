## 1. 模块概述

### 1.1 定位

本模块是**二维地图能力的基座**：其他模块（本项目主系统界面层，或任何第三方项目）不需要了解 MapLibre，只看《接口文档》就能把地图用起来——注入数据、调用接口，其余由本模块负责。

**设计原则**

| 原则 | 含义 |
|---|---|
| **性能优先** | 渲染性能与响应速度是首要指标；凡能提升性能的做法（图层/数据源策略、增量更新、缓存、懒加载、批次提交）都可采用，不因"改动大"而回避 |
| **接口完备** | 能力一律接口化：能被调用、能被查询、能被配置、能被关闭。凡是宿主可能需要的控制点，都必须有接口 |
| **文档先行** | 交付物含《接口文档》：看文档即可接入，无需读源码 |
| **独立自洽** | 模块代码不依赖任何业务后端；地图数据（瓦片）由宿主配置指向（本地瓦片服务或在线源），模块不内置瓦片 |
| **不夹带业务** | 不含业务逻辑、界面框架、数据获取 |

### 1.2 运行形态

| 形态 | 方式 | 说明 |
|---|---|---|
| 独立运行 | `npm run dev` → `http://localhost:5180/` | **模块自带的演示宿主**：自带示例图元、零业务后端依赖。用途是演示、调试、交付验证与性能基线测量。它的底图瓦片仍由配置指向；指向的服务不可用时回落纯色底 |
| 嵌入宿主 | `import { MapView, MapDraw } from '@map2d'` | 数据经 props 注入；宿主不出现 source/layer/样式概念 |

### 1.3 依赖与交付

| 项 | 内容 |
|---|---|
| 运行时依赖 | 仅 `maplibre-gl` / `react` / `zustand` |
| 交付形态 | 源码模块（**不发布 npm 包**，后续再议）；可整目录拷贝，可 `git subtree` 独立成仓 |
| 接口文档 | [接口文档.md](./接口文档.md)（接入的唯一依据） |
| 代码依赖边界 | 不依赖任何业务后端代码、宿主状态管理、宿主 UI 组件库 |
| 数据来源边界 | 瓦片由配置指向；**底图数据一律本地化**，不依赖联网在线源 |

### 1.4 范围边界

| 边界 | 内容 |
|---|---|
| 🚫 三维能力 | 地形、三维建筑、2D/3D 切换、楼层与室内 |
| 🚫 业务逻辑 | 阶段流程、目标台账、威胁评级、链路状态机 |
| 🚫 数据获取 | 业务数据一律由宿主注入（底图瓦片请求除外，那是渲染的必要条件） |
| 🚫 界面框架 | 左侧导航、业务面板、状态栏、顶栏 |
| 🚫 瓦片工程 | 切图、抓取、打包、分发 |
| 🚫 在线底图适配 | 不接国内在线底图源（天地图/高德等），不做坐标系偏移适配；底图一律本地化 |

> 前者只在国内在线底图源场景下需要，本项目底图一律本地化；后者与"每套底图整体替换"的定位冲突（见 §5 决策记录）。

## 3. 验收准则

**功能验收**

1. 独立运行 `npm run dev` 打开即出图（底图瓦片由配置指向）；
2. 地图漫游、缩放、二维锁定、视角命令均按 M2-MAP 各条通过；
3. 默认状态下不显示任何地图控件；按 M2-CTRL-01 / M2-API-05 逐个开启后，指北针、经纬度、缩放按钮、比例尺分别正确出现并可关闭；
4. 10 个图层分组可独立开关，状态跨底图切换保留；
5. 绘制接口覆盖 M2-DRAW-01 清单中的全部对象，且每个图元可按 M2-DRAW-03 单独显隐；
6. 手绘与编辑（M2-DRAW-08 / 12）在同一批交付内可用；
7. 回放：宿主加载带时间戳的轨迹后，可用模块时间轴播放/暂停/倍速/拖动定位（M2-DRAW-17 / 18 / M2-API-16）；
8. 多底图：声明"影像 + 路网"两套本地底图后，可任意互切且**整幅替换**，切换后视角、图元、图层开关、控件开关全部保持，宿主收到通知（M2-MAP-09 / M2-BASE-09 ~ 12）；
9. 按 M2-BASE-05 / M2-API-06 设定地面分辨率上限后，放大到更细层级不再请求新瓦片；该上限不影响在线样式底图（M2-BASE-13）。

**接口验收**

1. 宿主代码中不出现 `maplibre-gl` 的直接调用与模块内部路径；
2. 宿主传入的数据对象缺字段时不报错、按约定降级；
3. 导出/导入图元快照后画面一致；视图状态导出/恢复后画面一致；
4. 第三方按《接口文档》+《接入指南》能在自己的项目中跑起来。

**性能与可靠性验收**

1. 复现基准脚本（`examples/benchmark.ts`），各项耗时不超过 §4 基线；
2. 注入非法图元数据后，其余图元正常渲染（M2-NFR-10）；
3. 断开局域网瓦片后地图仍可打开与交互（M2-BASE-03 / M2-MAP-10）。

**交付验收**

1. `npm run typecheck`、`npm run build` 通过；
2. 模块目录可直接拷贝到新项目运行；
3. 独立子仓可 clone 后 `npm install && npm run dev` 出图。

## 4. 性能基线（本机实测，2026-06-11）

**测试环境**：Windows + 无头 Chrome（`--headless=new`，软件渲染 SwiftShader），画布 1582×748，模块独立宿主 `localhost:5180`。
**口径**：`set` = JS 侧把数据翻译为 GeoJSON 并提交给 MapLibre 的墙钟耗时；`回读` = 每帧把画布拷贝到 400×300 并取像素的中位耗时（反映渲染负载）；单机同口径可比。
**复现脚本**：[`examples/benchmark.ts`](../examples/benchmark.ts)（在独立宿主控制台加载后执行 `runBenchmark()`，输出同口径表格）。

| 负载 | 单次提交耗时 | 每帧像素回读 |
|---|---|---|
| 空载（仅底图） | — | 3.1 ms |
| 1,000 无人机点 | 1.2 ms | 2.6 ms |
| 5,000 无人机点 | 3.3 ms | 2.8 ms |
| 20,000 无人机点 | 15.2 ms | 3.1 ms |
| 50,000 无人机点 | 32.4 ms | 3.7 ms |
| 500 区域多边形 | 1.4 ms | 3.2 ms |
| 2,000 区域多边形 | 3.7 ms | 2.6 ms |
| 5,000 区域多边形 | 8.7 ms | 2.3 ms |
| 混合：5,000 点 + 500 面 + 500 线 + 500 标注 | 5.1 ms（合计） | 3.0 ms |
| 单点更新（遥测路径，300 点时） | 约 1.7 ms/次 | — |
| JS 堆占用（混合负载后） | 约 58 MB | — |

**结论与当前验收门槛建议**

1. **单次批量提交**：≤ 20,000 个点位或 ≤ 5,000 个多边形时，单次提交 ≤ 20 ms（一帧内可完成）→ 建议门槛：**20,000 点 / 5,000 面 单次提交 ≤ 20 ms**；
2. **单点更新**：≤ 2 ms/次 → 遥测 1 Hz / 10 Hz 场景余量充足（10 Hz × 300 点 = 约 5 ms/s）；
3. **渲染负载**：在当前口径下从空载到 50,000 点，回读耗时仅从 3.1 ms 增至 3.7 ms，**未观察到拐点**——说明该量级下瓶颈不在 MapLibre 渲染，而在数据翻译与提交（JS 侧）。

**尚未覆盖（需真机补测）**：无头软件渲染下无法反映 GPU 极限，因此**标签（text）数量**与**大面数填充**的真实上限需在目标终端（平板/办公机）上复测；建议补一份真机基线纳入 M2-NFR-11。

## 5. 决策记录

| 编号 | 议题 | 决策 | 影响 |
|---|---|---|---|
| D1 | 瓦片精度上限的**表达方式** | **按地面分辨率（米/像素）**表达（接口同时接受等效层级） | M2-BASE-05 / M2-API-06 参数形态 |

| D4 | 精度上限是否作用于在线底图 | **不作用**：在线底图随在线源；在线卡顿属在线源自身问题 | M2-BASE-13 |
| D5 | 手绘交互与图元编辑 | **同期做**（一次做完，不分批） | M2-DRAW-08 / 12 |
| D6 | 时间维度回放的实现分工 | **模块提供时间轴**（播放控制 + 按时刻渲染）；**数据与存储由宿主负责**，模块只提供加载/替换/清空接口 | M2-DRAW-17 / 18 / M2-API-16 |
| D7 | 多实例地图 | **纳入待完成**（不设"期"） | M2-NFR-08 |
| D8 | 军事标绘符号库标准 | **国军标（GJB）** | M2-DRAW-16 |
| D9 | 是否接国内在线底图源 | **否**：底图数据下载到本地后不再依赖在线源；坐标系适配需求随之取消 | 取消原 M2-MAP-08（坐标系适配） |
| D10 | 图元容量指标 | **以 §4 实测基线为准**（不再用拍脑袋数字） | M2-NFR-07 / 11 |
| D11 | 是否发布 npm 包 | **暂不发布**，后续再议 | 交付形态 |
| D12 | 底图包分类口径 | 按"**每一套完整底图**"组织：切哪套就**整幅替换**（卫星影像、路网、地形各为一套），不做同类混合 | M2-MAP-09 / M2-BASE-10；取消"影像+标注叠加/透明度"需求 |
| D13 | 多套底图的层级关系 | **单套生效**：同一时刻只有一套底图在显示，切换即整幅替换；不提供叠加层与透明度调节 | 同上 |
| D14 | 服务端是否下发底图清单 | **可选**：模块本身只要一份清单对象；清单从哪来由宿主决定（写在前端配置里，或由后端接口下发） | M2-API-10；后端接口属主仓契约范围 |
