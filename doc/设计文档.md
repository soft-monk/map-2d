## 1. 设计目标与约束

| 目标 | 落地方式 |
|---|---|
| **可独立交付** | 整目录可拷走、可 `git subtree` 独立成仓；只依赖 `maplibre-gl` / `react` / `zustand` |
| **数据与渲染解耦** | 模块只认 props（`MapData`）与绘制 API（`MapDraw`），不读宿主 store、不发业务请求 |
| **宿主零 MapLibre 知识** | 宿主代码里不出现 source/layer/样式；只用 `<MapView data>` + `MapDraw` + 少量命令 |
| **流畅优先** | 图元全部走 `source.setData()` 增量更新；地图/图元在 WebGL canvas，React 只管 DOM 面板 |
| **缺资源可降级** | 无瓦片 → 纯色底仍可打开；瓦片失败 → 只告警不隐藏图层 |
| **仅二维** | 锁定旋转与俯仰（`dragRotate/maxPitch`），态势图方向恒定 |

约束：不做 3D；不做手绘交互；不做数据获取（底图瓦片请求除外）；不定义后端接口（只消费配置形状）。

## 2. 分层与依赖规则

```
┌──────────────────────────────────────────────────────────────────────┐
│ 宿主（主系统 AppShell / 独立宿主 standalone）                          │
│   · 提供数据：MapData（业务 store → 适配器）                            │
│   · 装配界面：<MapView>{工具条/面板/指北针/清屏按钮}</MapView>            │
└───────────────┬──────────────────────────────────────────────────────┘
                │ 只经公开入口 src/index.ts
┌───────────────▼──────────────────────────────────────────────────────┐
│ ui/          MapView（唯一渲染入口）· MapToolbar · LayerPanel · Compass │
├──────────────────────────────────────────────────────────────────────┤
│ primitives/  MapDraw：9 类图元的增删改查 / 导入导出 / 重放               │
├──────────────────────────────────────────────────────────────────────┤
│ render/      LayerManager：source 与 layer 的建立、分组显隐、数据入口    │
├──────────────────────────────────────────────────────────────────────┤
│ core/        types（对外契约）· options（开关）· store（UI 状态）        │
│              commands（视角命令）· instance（地图实例单例）              │
└───────────────┬──────────────────────────────────────────────────────┘
                │ 仅此三个外部依赖
        maplibre-gl · react · zustand
```

**依赖规则（硬约束）**

| 规则 | 说明 |
|---|---|
| 单向依赖 | `ui → primitives → render → core`；反向引用一律禁止 |
| 单一实例 | MapLibre 实例只存于 `core/instance.ts` 的 `mapInstance`（`{ current }` 形态），任何模块都能取到，但不允许再 `new Map()` |
| 单一入口 | 宿主只能 `import ... from '@map2d'`（即 `src/index.ts`）；`ui/`、`render/` 内部文件不对宿主开放 |
| 无宿主耦合 | 模块内不出现宿主 store、组件库、后端地址；宿主结构兼容即可直接传（TS 结构化类型） |

## 3. 运行形态

| 形态 | 入口 | 说明 |
|---|---|---|
| **独立运行** | `src/standalone/main.tsx` → `npm run dev` → `http://localhost:5180/` | 自带示例数据（9 类图元 23 个）；控制条可切底图（本地瓦片/在线样式）、载入或清空示例图元、图层、清屏、复位视角 |
| **嵌入宿主** | 宿主 `import { MapView, MapDraw } from '@map2d'` | 主系统即此形态：`useMapData.ts` 适配器把业务 store 映射成 `MapData` |

独立宿主的定位是**调试与交付演示**：它是"模块能单独跑起来"的证据，也是新接入方的最小参考实现。它跟嵌入形态共用同一套 `MapView/LayerManager/MapDraw`，没有特殊分支。

> 独立宿主的 `vite.config.ts` 带一条 `/tiles → http://127.0.0.1:8080` 的开发代理：本地瓦片由主系统后端托管，独立运行时可借用；后端未启动也不报错——地图回落缺口底色。

## 4. 地图容器：MapView

`src/ui/MapView.tsx`（241 行）是**唯一渲染入口**，只做四件事。
### 4.1 初始化（挂载一次）

```
useEffect(只跑一次)
  ├─ 读挂载时的配置快照 bootRef.current.config（避免后续 props 变化重建地图）
  ├─ buildStyle(cfg) → 样式（见 4.2）
  ├─ new maplibregl.Map({ container, style, center, zoom, minZoom, maxZoom,
  │                       preserveDrawingBuffer: true,
  │                       dragRotate:false, pitchWithRotate:false, touchPitch:false, maxPitch:0,
  │                       attributionControl: MAP_OPTIONS.showAttribution ? {compact} : false })
  ├─ mapInstance.current = map            ← 全局单例
  ├─ addControl(NavigationControl(showCompass:false), 'top-right')
  ├─ addControl(ScaleControl({maxWidth:120, unit:'metric'}), 'bottom-left')
  ├─ on('load')  → LayerManager.init(map) → applyVisibility() → setReady(true)
  ├─ on('move'|'rotate') → 同步视口到模块 UI 状态（useMapUiStore.viewport）
  ├─ on('error') → 瓦片类错误**只累计告警**，不隐藏图层
  └─ 卸载 → map.remove()、mapInstance.current = null
```

设计取舍：

- **配置只在挂载时取一次**：地图重建代价高（重新请求瓦片、重放图元）。运行中的视角变化走 4.3 的 `easeTo`，底图变化走 4.4 的 `setStyle`，都不重建实例。
- **`preserveDrawingBuffer: true`**：允许把画布导出为图片（截图/汇报取图），代价是少量显存。
- **`LayerSync` 子组件在 `ready` 之后才挂载**：保证第一次同步发生在图层已建立之后，避免"数据先到、图层后到"的竞态。

### 4.2 样式装配（三种来源，一个优先级）

```
buildStyle(cfg):
  cfg.basemap.styleUrl        → 直接用样式 URL（矢量/栅格皆可，在线源走这条）
  cfg.basemap.tileUrlTemplate → rasterStyle()：本地栅格底图（下方三层结构）
  都没有                       → fallbackStyle()：纯色底（保证任何环境能打开）
```

本地栅格样式的**三层结构**（自下而上，`bg → base-underlay → base → base-tint`）：

| 层 | 类型 | 作用 |
|---|---|---|
| `bg` | background | 缺口"地面色" `#16283a`（深蓝灰而非纯黑，避免出现刺眼黑框） |
| `base-underlay` | raster | **低清叠底**：同一瓦片模板、`maxzoom: 6`，即只请求全球低清瓦片；快速拖动时任何新区域先有低清影像 |
| `base` | raster | 高清瓦片（`maxzoom: 14`），压暗 + 去饱和，做成指挥中心深色风格 |
| `base-tint` | background | 统一色调 `rgba(6,26,52,.16)`，只压在高清层之上（叠底保持较亮，缺口不被越描越黑） |

相关开关与常量（都在 `core/options.ts` 或文件顶部）：

| 名称 | 默认 | 作用 |
|---|---|---|
| `MAP_OPTIONS.showAttribution` | `false` | 是否显示版权署名；**关闭时同时不写入 `source.attribution`**（避免控件隐藏但样式里仍残留署名文本） |
| `MAP_OPTIONS.compactAttribution` | `true` | 署名紧凑模式 |
| `MAP_OPTIONS.rasterFadeDuration` | `0` | 栅格淡入时长；0 = 到达即显示，"低清→高清"替换是瞬时的 |
| `VOID_BG` / `GAP_BG` | `#08111f` / `#16283a` | 兜底底色 / 缺口底色 |
| `BASE_MAX_ZOOM` / `UNDERLAY_MAX_ZOOM` | `14` / `6` | 高清层与叠底层的最大级别 |

### 4.3 视角联动

| 触发 | 行为 |
|---|---|
| `data.config` 变化（换场景/任务） | `map.easeTo({ center, zoom, duration: 600 })` 平滑移动 |
| 宿主调用 `mapCommands.*` | 直接作用于 `mapInstance`（`setView/flyTo/focus/resetView/zoomBy/getViewport/isReady`） |
| 用户拖拽/缩放 | `move`/`rotate` 事件回写 `useMapUiStore.viewport`，供宿主显示坐标/层级 |

### 4.4 底图热切换（关键细节）

```
basemapKey = styleUrl | tileUrlTemplate        ← 只有这两个字段变化才触发
useEffect(basemapKey):
  首次渲染跳过（初始化已建好样式）
  map.setStyle(buildStyle(config))
  map.once('styledata'):
      if (!map.getSource('src-area')) {      ← setStyle 会清空全部 source/layer
          LayerManager.init(map)             ← 重建 source 与 layer
          LayerManager.applyVisibility()     ← 恢复用户此前的图层开关
      }
      MapDraw.render()                       ← 重放绘制 API 的全部图元
```

这就是"换底图不丢图元"的实现方式：**图层重建 + 图元重放**，而不是把图元也交给样式。`src-area` 的存在被当作"图层已建立"的探针，避免 `styledata` 多次触发时重复建层。

## 5. 图元渲染：LayerManager

`src/render/LayerManager.ts`（562 行）：模块内部唯一接触 MapLibre source/layer 的地方。

### 5.1 数据源与图层清单

10 个 GeoJSON source（`src-area` `src-link` `src-group` `src-target` `src-uav` `src-scan` `src-track` `src-trail` `src-pulse` `src-mark`），对应 18 个图层，按分组组织：

| 分组（`LayerGroup`） | 中文名 | 组成图层 |
|---|---|---|
| `area` | 任务区域 | 填充 + 虚线描边 |
| `pulse` | 脉冲标记 | 扩散圆环（rAF 驱动） |
| `scan` | 扫描覆盖 | 半径圆（像素半径按缩放换算） |
| `link` | 数据链路 | 发光主线 + 状态线 |
| `group` | 集群编组 | 圆点 + 标签 |
| `track` | 目标轨迹 | 虚线轨迹 |
| `trail` | 飞行尾迹 | 尾迹线（航迹历史） |
| `target` | 目标/锁定框 | 光晕 + 圆 + 标签（选中放大） |
| `uav` | 无人机/航迹 | 光晕 + 点 + 标签 |
| `mark` | 标注/标记 | 标注点 + 文本 |

### 5.2 分组显隐（多源融合图层要求）

```
setGroupVisible(group, visible) → hidden: Set<LayerGroup> → applyVisibility()
applyVisibility(): 对 ALL_LAYER_GROUPS 逐组 setLayoutProperty(id,'visibility', …)
```

`hidden` 集合**跨样式重建保留**：换底图或重进页面后，用户此前的开关状态由 `applyVisibility()` 恢复（M2-15 的验收点）。

### 5.3 两类数据入口

| 入口 | 面向 | 代表方法 |
|---|---|---|
| **业务侧**（给数组即出图） | 宿主业务数据 | `setTargets(targets, selectedId)`、`setGroups`、`setUavs`、`setLinks(edges, nodes)`、`setTrack(points)`、`setScenario(key)`、`setPhase(phase)` |
| **坐标显式**（宿主自绘） | 绘制 API 与高级用法 | `setAreaFeatures`、`setScanFeatures`、`setPulseSeedsPublic`、`setMarkers`、`setLinkFeatures`、`setGroupFeatures`、`setTargetFeatures`、`setUavFeatures`、`setTrackFeatures`、`clearAll` |

两类入口最终都落到 `source.setData()`，**不重建图层**——这是"动态图层更新不卡顿"的前提。

## 6. 绘制 API：MapDraw

`src/primitives/api.ts`（255 行）：宿主与模块之间的**图元级契约**，屏蔽全部 MapLibre 细节。

### 6.1 数据流

```
宿主调用                     模块内部
MapDraw.set('area', [...])  → bags.area: Map<id, AreaItem>        ← 集合管理（增删改查的真相源）
                            → renderKind('area')                  ← 该类型的转换 + setData
                            → LayerManager.setAreaFeatures(FC)     ← 业务图元 → GeoJSON → 图层
MapDraw.export()            ← 各 bags 的副本（可 JSON 序列化，便于存档/交付）
MapDraw.load(snapshot)      → 对每类执行 set()（整体覆盖）
MapDraw.render()            → renderAll()（9 类全量重放；换底图后调用）
```

### 6.2 九类图元与关键字段

| 类型 | 关键字段 | 渲染要点 |
|---|---|---|
| `area` 区域 | `polygon`（首尾不必闭合，模块自动闭合）、`color`、`dashed`、`opacity` | 填充 + 虚线描边 |
| `drone` 无人机 | `lng/lat`、`type`（optical/radar/electronic/comm） | 按类型取调色板；点位 + 标签 |
| `target` 目标 | `lng/lat`、`threat`、`status`、`selected` | `status` 优先于 `threat` 决定颜色；`selected` 触发锁定框放大 |
| `link` 链路 | `from/to`、`state`（green/yellow/red） | 状态决定实线/虚线 + 颜色 |
| `track` 轨迹 | `points[]`、`dashed` | 虚线轨迹 |
| `scan` 扫描 | `lng/lat`、**`radiusKm`** | 公里 → 像素，`zoomend` 时重算 |
| `pulse` 脉冲 | `lng/lat`、`color` | 外围扩散环（模块内部 rAF 动画） |
| `cluster` 集群 | `lng/lat`、`name`、`color` | 圆点 + 名称标签 |
| `label` 标注 | `lng/lat`、`text`、`color`、`size`、`radius` | 文本标注（`radius:0` 表示不画点） |

### 6.3 调色板（未显式给色时的缺省）

```
威胁   high #ef4444 ｜ mid #f59e0b ｜ low #22d3ee
状态   red  #ef4444 ｜ yellow #f59e0b ｜ gray #8b93a7
无人机 optical #22d3ee ｜ radar #f59e0b ｜ electronic #a855f7 ｜ comm #22c55e
链路   green #22c55e ｜ yellow #f59e0b ｜ red #ef4444
其它   区域 #22d3ee ｜ 轨迹 #ef4444 ｜ 扫描 #38bdf8 ｜ 脉冲 #22d3ee ｜ 集群 #8b5cf6 ｜ 标注 #cfe3f5
```

**数据与样式解耦**：图元自带 `color/label/selected/...`；未给才用调色板。因此宿主换配色不需要改模块，模块换配色也不影响宿主数据。

### 6.4 公里 → 像素

```
kmToPixels(km, lat) = max(2, km*1000 / metersPerPixel)
metersPerPixel = 156543.03392 * cos(lat) / 2^zoom
```

扫描半径因此是**真实地理尺度**，且随缩放自适应（`zoomend` 钩子在有扫描图元时才注册，避免空转）。

## 7. 状态、命令与开关

### 7.1 模块 UI 状态（`core/store.ts`，Zustand）

| 字段 | 含义 | 谁改 |
|---|---|---|
| `clearMode` | 清屏开关量 | 宿主（清屏按钮）；**"隐藏哪些面板"由宿主执行**，模块只置位 |
| `activeTool` | 当前工具（select/measure/layer/area/new/clear/full/draw/reset） | 工具条 |
| `layersOpen` | 图层面板展开 | 工具条 |
| `hiddenGroups` | 被关掉的图层分组 | 图层面板（并同步给 LayerManager） |
| `viewport` | 视口（lng/lat/zoom/bearing） | 地图事件回写 |
| `displayMode` | 显示模式（10 种取值） | store 提供 `setDisplayMode()`；当前由宿主按场景+阶段写入（手动切换 UI 未做） |

补充：`hiddenGroups` 的初值取自 `LayerManager.hiddenGroups()`（模块 UI 状态与渲染状态同源）；`toggleGroup()` 一边改 `LayerManager` 一边回写 store，保证面板显示与实际渲染一致。

**边界**：这里只有"地图相关"的 UI 状态，没有业务状态。宿主业务状态（目标、阶段、任务）永远不进模块。

### 7.2 视角命令（`core/commands.ts`）

`setView` / `flyTo` / `focus(lng,lat,zoom)` / `resetView(config)` / `zoomBy(delta)` / `getViewport()` / `isReady()` —— 给宿主"不改数据也能动镜头"的能力（例如"定位到某目标"）。实现上都是对 `mapInstance.current` 的薄封装，`isReady()` 用于宿主等待地图可用。

### 7.3 模块开关（`core/options.ts`）

集中一处、改一个数就生效：`showAttribution`（合规）、`compactAttribution`、`rasterFadeDuration`。设计原则是**合规与观感类开关不出现在业务代码里**，便于交付后由使用方自行决定（例如署名显示）。

## 8. 与宿主的接入

### 8.1 契约：`MapData`

宿主只需组装这一个对象（`core/types.ts`）：

```ts
interface MapData {
  config: MapConfigData | null           // 视角 + 底图（center/zoom/minZoom/maxZoom/basemap）
  scenarioKey: string                    // 场景（影响区域配色等）
  phase: Phase                           // 阶段（影响显示模式等）
  targets: Target[]                      // 目标台账（含 threat/status）
  selectedTargetId?: string | null       // 当前选中（锁定框）
  groups: Group[]                        // 集群编组
  uavs: UavPosEvent[]                    // 无人机实时位置
  edges: LinkEdge[]                      // 链路边
  topology: LinkTopology | null          // 链路拓扑（提供节点坐标）
  track: TargetTrackPoint[]              // 目标轨迹点
}
```

结构兼容即可（TS 结构化类型）：宿主若有自己的 DTO，字段对得上就能直接传，不要求引用模块类型。

### 8.2 主系统接入方式（示例实现）

| 关注点 | 做法 |
|---|---|
| 别名 | `vite.config.ts`：`'@map2d' → ../map-2d/src/index.ts`；`tsconfig.json` 同步 `paths` |
| 唯一适配器 | `src/app/useMapData.ts`：业务 store → `MapData`。**换数据源只改这一个文件** |
| 装配 | `app/AppShell.tsx`：`<MapView data={mapData}>` 内放工具条、图层面板、指北针、清屏按钮 |
| 清屏 | 宿主负责隐藏顶栏/右侧面板/阶段面板/语音/视频/告警浮层，只留左侧导航 + 底部状态栏 + 地图 |
| 瓦片与配置 | 后端 `/api/v1/map/config` 下发 `tileUrlTemplate` 与视角；瓦片由后端静态托管 |

## 9. 关键设计决策与取舍

| # | 决策 | 理由 | 代价 / 边界 |
|---|---|---|---|
| D1 | **数据经 props 注入，模块不取数** | 模块可脱离任何后端运行；宿主数据源可任意替换 | 宿主必须写适配器（主系统即 `useMapData.ts`） |
| D2 | **绘制 API 与渲染分离**（`MapDraw` ↔ `LayerManager`） | 宿主只见图元语义；渲染细节可整体替换（如换 deck.gl） | 多一层集合管理（`bags`）与转换代码 |
| D3 | **图元增量更新**（`setData` 而非重建图层） | 动态图层高频更新不卡顿 | 图元风格受 GeoJSON 表达力限制（如逐要素虚线需在属性里表达） |
| D4 | **地图实例单例**（`mapInstance`） | 绘制 API/命令/宿主都需要拿到实例；多实例会带来样式与图层归属混乱 | 一个页面只能有一个地图容器（当前需求满足） |
| D5 | **样式重建后重放图元** | `setStyle` 必然清空 source/layer，重放比"把图元塞进样式"更简单可控 | 重放是一次全量 `setData`（图元量大时有一次性开销） |
| D6 | **缺口底色用深蓝灰、栅格不淡入** | 观感上"没有黑框"；淡入会在过渡期露出半透明底 | 观感问题未彻底解决——缩放/拖拽时仍可能出现整屏底色（见需求文档 M2-14，暂缓） |
| D7 | **低清叠底层固定 `maxzoom: 6`** | 瓦片是四叉树，MapLibre 本就会用父瓦片兜底；把 z0–6 常驻成独立图层，拖动时先有低清影像 | 与高清层共用模板，低层级会被请求两次（浏览器缓存去重） |
| D8 | **二维锁定** | 态势图方向恒定，指北针恒指正北；避免操作中迷失方向 | 无法查看倾斜/旋转视角（本就不在范围内） |
| D9 | **模块开关集中**（`MAP_OPTIONS`） | 合规与观感类开关不散落各文件，交付后使用方可自行决定 | 需要重建样式才能生效的开关（如署名）不会热更新 |
| D10 | **不引入状态管理库之外的东西**（只用 zustand 管模块 UI 状态） | 依赖面最小，便于整目录拷贝 | 模块内状态与宿主状态是两套，需要显式同步（viewport 回写、hiddenGroups 同步） |

## 10. 已知边界与扩展点

### 10.1 已知边界

| 边界 | 现状 |
|---|---|
| 单实例 | 一个页面一个地图（D4）；要"第二屏独立态势图"需再开页面/路由，模块本身不提供多实例管理 |
| 手绘交互缺失 | `MapToolbar` 的测距/区域/新建/标绘为占位（`disabled` + tooltip）；图元只能由 API 驱动 |
| 显示模式只读 | 随场景+阶段自动展示，不接受手动切换 |
| 缺口观感 | 缩放/拖拽时可能出现整屏深蓝底色（M2-14 暂缓） |
| 在线底图依赖外网 | `styleUrl` 走外网时断网不可用；本地瓦片不受影响 |
| 瓦片层级上限 | 高清层 `maxzoom: 14`（与预切瓦片一致）；更深的层级没有数据 |

### 10.2 扩展点（新增能力时的落点）

| 想加的能力 | 落点 |
|---|---|
| 新图元类型（如热力图、预测轨迹、覆盖边界） | ① `PrimitiveKind` 增一类 ② `LayerManager` 增 source+layer ③ 若需分组则在 `LayerGroup/GROUP_LAYERS/LAYER_GROUP_LABELS` 登记 ④ `index.ts` 导出类型 |
| 手绘交互 | 新增 `ui/` 下的交互层，复用 `MapDraw` 写入；不改渲染层 |
| 显示模式手动切换 | `core/store.ts` 的 `displayMode` 增加 setter，工具条加下拉 |
| 多实例地图 | 需要把 `mapInstance` 单例改为按容器 id 的注册表——**这是破坏性改动**，需先评估宿主用法 |
| 观感优化（M2-14） | 见需求文档 §6：方案与实测数据已留档，历史实现见提交 `caf4e59` / `cbec72e` |
| 打包发布（npm） | `package.json` 的 `private` 改 false + 补 `files/exports`；当前为源码交付 |
