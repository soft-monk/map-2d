# map-2d · 触屏设备验收清单（M2-NFR-09 移动端手势一致性）

- 版本：v1.0
- 日期：2026-09-12
- 对应需求：**M2-NFR-09**（移动端手势一致性：平板/触屏上双指缩放、单指拖动、长按选择、双击缩放均可用）
- 用途：**本项需在真实触屏设备上验收**。无头环境只能派发合成触摸事件，不足以作为验收依据（见 §3 证据等级）。

---

## 1. 怎么验（10 分钟）

1. 在**与平板同一局域网**的机器上启动独立宿主：
   ```bat
   cd /d <你的路径>\mapApp\map-2d
   npm run dev:host
   ```
2. 平板浏览器打开 `http://<那台机器的IP>:5180/`（**必须用 `dev:host`**，普通 `dev` 只监听本机）；
3. 按 §2 表格逐项操作，把结果记在"实测"列；
4. 有任何一项不符合"预期现象"，把**机型 + 浏览器版本 + 现象**记下来反馈。

> 提示：页面右侧是「功能验收台」，顶栏有"绘制"按钮组与"控件"勾选框，下面的用例会用到。

## 3. 证据等级（说明为什么这一项在文档里仍是 ⏳）

| 等级 | 手段 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| **A. 真机实测** | 按 §2 在平板上操作 | **可判 ✅**（需求要求的口径） | — |
| **B. 合成触摸事件** | 无头 Chrome 派发 `TouchEvent` | 手势处理器**接得住**：单指拖动确实平移、双指张开确实缩放、绘制态确实禁用拖拽 | 真机上的**手势仲裁**（浏览器是否把手势给页面）、长按菜单行为、多指抖动容错、性能体感 |
| **C. 静态检查** | 读代码 / 能力探测 | 旋转已禁用（`dragRotate.isEnabled() === false`）、`touchZoomRotate` 处于启用态 | 同上 |

**B 级已完成的验证结果（2026-09-12，无头 Chrome + `Emulation.setTouchEmulationEnabled`）**：

| 检查项 | 结果 |
|---|---|
| 单指拖动（合成 touchstart → 10 次 touchmove → touchend） | 中心经度 116.3974 → **116.41247**，地图确实平移 |
| 双指捏合（两指间距 80px → 320px，即 4 倍） | 层级 12 → **14.18**（+2.18 级；理论上 `log₂4 = 2` 级，吻合） |
| 绘制模式下的手势冲突 | 常规 dragPan=true → 绘制时 **false** → 退出后 **true** |
| 旋转能力 | `dragRotate` 已禁用（符合二维锁定） |

> 结论：**B 级通过**（处理器与冲突处理都正确），但**不能替代 A 级**。
> 因此需求文档中 M2-NFR-09 保持 ⏳，直至有人按 §1 在真机上勾完 §2。

## 4. 如果发现不符合预期

优先检查这三处（其余按现象定位）：

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 双指旋转时地图跟着转 | 宿主自建了 Map 实例且未禁 `dragRotate`/`touchPitch` | 用模块的 `<MapView>`；或自行设 `dragRotate: false, touchPitch: false` |
| 长按弹出浏览器菜单 | 浏览器默认行为（部分 Android 浏览器） | 模块已在画布上禁用 `contextmenu`；若仍出现，记录机型与浏览器版本反馈 |
| 绘制态下地图仍平移 | 未通过 `mapCommands.setDrawMode()` 进入绘制（例如自己实现了绘制 UI） | 用 `DrawLayer`，或自行 `map.dragPan.disable()` |
