## 1. 设计目标与约束

| 目标 | 落地方式 |
|---|---|
| **可独立交付** | 整目录可拷走、可独立成仓；运行时只依赖 `maplibre-gl` / `react` / `zustand` 三个外部包 |
| **数据与渲染解耦** | 模块只认 props（`MapData`）与绘制 API（`MapDraw`）；不读宿主的任何状态容器、不发起业务请求 |
| **宿主零渲染内核知识** | 宿主代码中不出现 source / layer / style 概念；只用 `<MapView data={...}>` + `MapDraw` + 少量命令接口 |
| **无内置业务** | 模块内不存在任何具体宿主的业务名词、枚举、规则、字段与地址；业务规则一律由宿主注入 |
| **流畅优先** | 图元全部走 `source.setData()` 增量更新；地图与图元在 WebGL 画布，React 只负责 DOM 浮层 |
| **缺资源可降级** | 无瓦片 → 纯色底仍可打开；瓦片失败 → 只汇总告警、不隐藏图层 |
| **仅二维** | 锁定旋转与俯仰（`dragRotate` / `maxPitch`），态势图方向恒定 |

**设计约束**

| 约束 | 说明 |
|---|---|
| 不做三维 | 地形、三维建筑、2D/3D 切换、楼层室内 |
| 不做业务逻辑 | 业务流程与阶段规则、台账与评级、链路状态机、任务编排 |
| 不做数据获取与存储 | 业务数据、回放数据、快照存档的采集与持久化均由宿主负责 |
| 不定义后端接口 | 模块只消费配置对象的**形状**，不约定任何具体接口路径 |
| 不假设宿主形态 | 不假设宿主的目录结构、构建工具、端口、后端、仓库地址与发布方式 |

## 2. 解耦基准与设计口径

### 2.1 六条基准（与《需求文档-解耦版》§0.2 一致）

| 编号 | 基准 | 在设计上的体现 |
|---|---|---|
| B1 | 单向依赖（只允许 `宿主 → 模块`） | 模块不 import 任何宿主代码；宿主通过 props / 命令接口 / 配置对象驱动模块 |
| B2 | 可离线自证 | 独立宿主（`src/standalone/`）不依赖任何服务即可启动；瓦片缺失时回落纯色底 |
| B3 | 无内置业务 | 上下文映射、模式标签、符号语义、数据分级全部走"宿主注入 + 通用缺省" |
| B4 | 配置可替换 | 地址、模板、视角、精度上限全部来自配置对象或环境变量 |
| B5 | 契约自带 | 对外类型全部在 `src/core/types.ts` 定义；宿主结构兼容即可传 |
| B6 | 外部依赖登记 | 见 §11（外部依赖与配置外置） |

### 2.2 三条设计口径

1. **能力与策略分离**：模块提供"能力"（能画、能算、能切），策略（画什么、什么时候画、按什么规则显示）由宿主提供或使用通用缺省。
2. **状态归属单一**：宿主业务状态永不进入模块；模块自身的 UI 状态、渲染状态、绘制状态内部同源（不出现两份真相）。
3. **副作用可撤销**：模块产生的监听器、定时器、动画帧、全局标记全部有对应的释放路径，卸载即回到宿主原状。

```
└───────────────┬──────────────────────────────────────────────────────┘
                │ 只经公开入口 src/index.ts（唯一入口）
┌───────────────▼──────────────────────────────────────────────────────┐
│ ui/          MapView（唯一渲染入口）· MapToolbar · LayerPanel ·        │

├──────────────────────────────────────────────────────────────────────┤
│ render/      LayerManager：数据源与图层的建立、分组显隐、透明度、排序、  │
│              数据入口（业务侧 / 坐标显式）                             │
├──────────────────────────────────────────────────────────────────────┤
│ core/        types（对外契约）· options（开关）· store（模块 UI 状态）   │
│              commands（命令门面）· instance/instanceRegistry（实例）     │
│              controls · basemaps · tilePrecision · tileFallback ·       │
│              tileNet · tileValidation · grid · displayModeState ·       │
│              theme · symbols · clustering · annulus · replay ·          │
│              geometry · interaction · degrade · resources ·             │
│              perfBaseline · diagnostics · viewState · validate          │
└───────────────┬──────────────────────────────────────────────────────┘
                │ 仅此三个运行时依赖
        maplibre-gl · react · zustand
```

**依赖规则（硬约束）**

| 规则 | 说明 |
|---|---|
| 单向依赖 | `ui → primitives → render → core`；反向引用一律禁止 |
| 单一入口 | 宿主只能 `import ... from '<模块入口>'`（即 `src/index.ts`）；`ui/`、`render/`、`core/` 内部文件不对宿主开放 |
| 实例归属单一 | 渲染内核实例只存于实例注册表；任何模块都通过"取当前实例"访问，不允许再 `new Map()` |
| 无宿主耦合 | 模块内不出现宿主的状态容器、组件库、后端地址、目录结构 |
| 无内置地址 | 模块内不出现任何指向具体主机、端口、目录、服务的默认值 |
| 接口完备优先 | 凡是宿主可能需要控制的点都要有接口（显示/隐藏/查询/配置），不做"写死在内部"的实现 |

## 4. 运行形态

| 形态 | 入口 | 说明 |
|---|---|---|
| **独立运行** | `src/standalone/main.tsx` → `npm run dev` | 模块自带的演示宿主：自带示例图元、零业务后端依赖。底图瓦片由配置指向；指向的服务不可用时回落纯色底。用途：演示、调试、交付验证、性能基线测量、**功能与触屏验收**（验收不接入任何宿主业务系统） |
| **嵌入宿主** | 宿主 `import { MapView, MapDraw } from '<模块入口>'` | 宿主自行实现适配层（业务数据 → `MapData`）。适配层写在宿主侧，模块不感知其存在 |
| **多实例嵌入** | `<MapView instanceId="A" data={...} />` | 同页多实例，各自独立样式/数据源/图层/相机/控件；模块级操作作用于"当前实例" |

> **独立宿主的设计定位**：它是"模块能单独跑起来"的证据，也是新接入方的最小参考实现。它与嵌入形态共用同一套 `MapView` / `LayerManager` / `MapDraw`，**没有特殊分支**。
>
> **开发期地址**：独立宿主所需的瓦片目录与可选联调代理全部由**环境变量/配置文件**提供（见 §11.3），模块源码内不存在任何默认地址。

## 5. 地图容器：MapView

`src/ui/MapView.tsx`（346 行）是**唯一渲染入口**，只做四件事。

### 5.1 初始化（挂载一次）

```
useEffect(只跑一次)
  ├─ 读挂载时的配置快照 bootRef.current.config（避免后续 props 变化重建地图）
  ├─ buildStyle(cfg) → 样式（见 5.2）
  ├─ new maplibregl.Map({ container, style, center, zoom, minZoom, maxZoom,
  │                       preserveDrawingBuffer: MAP_OPTIONS…,
  │                       dragRotate:false, pitchWithRotate:false, touchPitch:false, maxPitch:0,
  │                       attributionControl: MAP_OPTIONS.showAttribution ? {compact} : false })
  ├─ 注册进实例注册表（instanceId 缺省用保留 id）
  ├─ applyControls(map)          ← 按控件开关状态决定挂载哪些控件（默认全不挂载）
  ├─ on('load')  → LayerManager.init(map) → applyVisibility() → setReady(true)
  ├─ on('move'|'rotate') → 同步视口到模块 UI 状态（useMapUiStore.viewport）
  ├─ on('error') → 瓦片类错误只累计告警，不隐藏图层
  └─ 卸载 → 解绑监听/钩子、停止巡检与动画、注销实例、map.remove()
```

**设计取舍**

| 取舍 | 理由 | 代价 |
|---|---|---|
| 配置只在挂载时取一次 | 地图重建代价高（重新请求瓦片、重放图元） | 运行中改视角须走命令接口或改 `config` 对象 |
| `preserveDrawingBuffer` 默认开启 | 支持画布导出为图片 | 少量显存；已登记为可优化项（按需开启） |
| `LayerSync` 子组件在 `ready` 之后才挂载 | 保证首次同步发生在图层建立之后，避免"数据先到、图层后到"的竞态 | 首帧多一次渲染调度 |
| 控件"能力存在但不自动挂载" | 守住"宿主不接触渲染内核"的边界（宿主不必自己 `addControl`） | 模块需维护控件生命周期，样式重建后按状态恢复 |

### 5.2 样式装配（三种来源，一个优先级）

```
buildStyle(cfg):
  cfg.basemap.styleUrl        → 直接用样式 URL（矢量/栅格皆可）
  cfg.basemap.tileUrlTemplate → rasterStyle()：本地栅格底图（三层结构）
  都没有                       → fallbackStyle()：纯色底（保证任何环境能打开）
```

本地栅格样式的**三层结构**（自下而上 `bg → base-underlay → base → base-tint`）：

| 层 | 类型 | 作用 |
|---|---|---|
| `bg` | background | 缺口"地面色"（深蓝灰而非纯黑，避免出现刺眼黑框） |
| `base-underlay` | raster | **低清叠底**：同一模板、`maxzoom` 取低层级；快速拖动时任何新区域先有低清影像 |
| `base` | raster | 高清瓦片（`maxzoom` 取模板支持的上限），压暗 + 去饱和 |
| `base-tint` | background | 统一色调叠色 |

相关开关与常量（`src/core/options.ts` 与样式模块）：

| 名称 | 默认 | 作用 |
|---|---|---|
| `MAP_OPTIONS.showAttribution` | `false` | 是否显示版权署名；**关闭时同时不写入来源署名**（避免控件隐藏但样式里仍残留文本） |
| `MAP_OPTIONS.compactAttribution` | `true` | 署名紧凑模式 |
| `MAP_OPTIONS.rasterFadeDuration` | `0` | 栅格淡入时长；0 = 到达即显示，"低清→高清"替换瞬时完成 |
| `VOID_BG` / `GAP_BG` | 兜底色 / 缺口色 | 无瓦片兜底与缺口观感 |
| `BASE_MAX_ZOOM` / `UNDERLAY_MAX_ZOOM` | 高清层 / 叠底层上限 | 与预切瓦片层级一致；可被精度上限进一步压紧 |

### 5.3 视角联动

| 触发 | 行为 |
|---|---|
| `data.config` 变化 | `easeTo({ center, zoom, duration })` 平滑移动（时长可配，默认 600 ms） |
| 宿主调用命令接口 | 直接作用于当前实例（`setView` / `flyTo` / `focus` / `resetView` / `zoomBy` / `getViewport` / `isReady`） |
| 用户拖拽/缩放 | `move` / `rotate` 事件回写模块 UI 状态，供宿主显示坐标与层级 |

### 5.4 底图热切换（关键细节）

```
basemapKey = styleUrl | tileUrlTemplate        ← 只有这两个字段变化才触发
useEffect(basemapKey):
  首次渲染跳过（初始化已建好样式）
  map.setStyle(buildStyle(config))
  map.once('styledata'):
      if (!map.getSource('<区域源 id>')) {     ← 探针：setStyle 会清空全部 source/layer
          LayerManager.init(map)               ← 重建数据源与图层
          LayerManager.applyVisibility()       ← 恢复用户此前的图层开关
          …其余扩展层（手绘预览、网格等）按各自幂等入口重建
      }
      MapDraw.render()                         ← 重放绘制 API 的全部图元
```

这就是"换底图不丢图元"的实现方式：**图层重建 + 图元重放**，而不是把图元交给样式。以"区域数据源是否存在"作为"图层已建立"的探针，避免 `styledata` 多次触发时重复建层。

## 6. 图元渲染：LayerManager

`src/render/LayerManager.ts`（910 行）：模块内部**唯一接触渲染内核 source/layer 的地方**。

### 6.1 数据源与图层清单（14 源 / 28 图层 / 13 分组）

| 分组（`LayerGroup`） | 中文名 | 数据源 | 组成图层 |
|---|---|---|---|
| `area` | 任务区域 | `src-area` | 填充 + 虚线描边 |
| `link` | 数据链路 | `src-link` | 发光主线 + 状态线 |
| `group` | 集群编组 | `src-group` | 圆点 + 标签 |
| `target` | 目标/锁定框 | `src-target` | 光晕 + 圆 + 标签（选中放大） |
| `uav` | 无人机/航迹 | `src-uav` | 光晕 + 点 + 标签 |
| `scan` | 扫描覆盖 | `src-scan` | 半径圆（像素半径按缩放换算） |
| `track` | 目标轨迹 | `src-track` | 虚线轨迹 |
| `trail` | 飞行尾迹 | `src-trail` | 尾迹线（航迹历史） |
| `pulse` | 脉冲标记 | `src-pulse` | 扩散圆环（动画帧驱动） |
| `mark` | 标注/标记 | `src-mark` | 标注点 + 文本 |
| `route` | 航线/图形区 | `src-route`、`src-shape` | 航线（实线/虚线/发光）+ 圆形·椭圆·目标区（填充/实线/虚线） |
| `annulus` | 圈层/参考线 | `src-annulus` | 距离环·方位线·方位圈·九宫格（实线 + 虚线） |
| `symbol` | 标绘符号 | `src-symbol` | 图标 + 标签 |

> **数量口径**：以上为**代码实际值**（13 分组 / 14 源 / 28 图层）。历史文档中的"10 源 / 18 图层 / 10 分组"为旧值，已失效；《需求文档-解耦版》M2-LAYER-01 的 11 组口径同样需要按本节校正（见 §14.4 待办）。

### 6.2 分组显隐（多源融合图层要求）

```
setGroupVisible(group, visible) → hidden: Set<LayerGroup> → applyVisibility()
applyVisibility(): 对 ALL_LAYER_GROUPS 逐组 setLayoutProperty(id, 'visibility', …)
```

`hidden` 集合**跨样式重建保留**：换底图或重进页面后，用户此前的开关状态由 `applyVisibility()` 恢复。

### 6.3 两类数据入口

| 入口 | 面向 | 代表方法 |
|---|---|---|
| **业务侧**（给数组即出图） | 宿主的批量数据 | `setTargets`、`setGroups`、`setUavs`、`setLinks`、`setTrack` |
| **坐标显式**（宿主自绘） | 绘制 API 与高级用法 | `setAreaFeatures`、`setScanFeatures`、`setPulseSeedsPublic`、`setMarkers`、`setLinkFeatures`、`setGroupFeatures`、`setTargetFeatures`、`setUavFeatures`、`setTrackFeatures`、`clearAll` |

两类入口最终都落到 `source.setData()`，**不重建图层**——这是"动态图层更新不卡顿"的前提。

### 6.4 上下文与可见性（解耦后的口径）

| 项 | 设计 |
|---|---|
| 上下文来源 | 上下文标识（场景/流程编号）与阶段值属于**宿主上下文**，由 `MapData` 可选传入；模块只用它做两件事：查宿主注入的映射表、驱动模式标签 |
| 未注入映射时 | **全部图元按分组开关显示**（不隐藏任何分组），即"无业务规则"行为 |
| 注入映射后 | 按映射表与分组开关取交集；映射表由宿主提供，模块内没有任何具体上下文常量 |
| 与旧实现的差别 | 旧版在模块内硬编码了"某阶段不显示目标/集群/轨迹"与"某场景绑定某城市坐标"，属业务语义泄漏，已按《需求文档-解耦版》M2-MZ-01-02/03 移除 |

## 7. 绘制 API：MapDraw

`src/primitives/api.ts`（681 行）：宿主与模块之间的**图元级契约**，屏蔽全部渲染内核细节。

### 7.1 数据流

```
宿主调用                       模块内部
MapDraw.set('area', [...])  → bags.area: Map<id, AreaItem>      ← 集合管理（增删改查的真相源）
                            → renderKind('area')                ← 该类型的校验 + 转换
                            → LayerManager.setAreaFeatures(FC)   ← 图元 → GeoJSON → 数据源
MapDraw.export()            ← 各 bags 的副本（可 JSON 序列化，便于存档/交付）
MapDraw.load(snapshot)      → 对每类执行 set()（整体覆盖）
MapDraw.render()            → renderAll()（全类重放；换底图后调用）
MapDraw.batch(fn)           → 批次内只改集合，退出时对受影响类型各提交一次
```

### 7.2 图元类型与关键字段

| 类型 | 关键字段 | 渲染要点 |
|---|---|---|
| `area` 区域 | `polygon`（首尾不必闭合，模块自动闭合）、`color`、`dashed`、`opacity` | 填充 + 虚线描边 |
| `drone` 无人机 | `lng/lat`、`type` | 按类型取调色板；点位 + 标签 |
| `target` 目标 | `lng/lat`、`threat`、`status`、`selected` | `status` 优先于 `threat` 决定颜色；`selected` 触发锁定框放大 |
| `link` 链路 | `from/to`、`state` | 状态决定实线/虚线 + 颜色 |
| `track` 轨迹 | `points[]`、`dashed` | 虚线轨迹 |
| `route` 航线 | `points[]`、`dashed` | 折线（实线/虚线/发光三选） |
| `shape` 圆形/椭圆/目标区 | `lng/lat`、`radiusKm`、`kind`、`rotation`、短半轴 | 按 `kind` 取内置语义配色；半径按公里换算 |
| `scan` 扫描 | `lng/lat`、`radiusKm` | 公里 → 像素，缩放结束时重算 |
| `pulse` 脉冲 | `lng/lat`、`color` | 外围扩散环（模块内动画帧驱动） |
| `cluster` 集群 | `lng/lat`、`name`、`color` | 圆点 + 名称标签 |
| `label` 标注 | `lng/lat`、`text`、`color`、`size`、`radius`、`minZoom` | 文本标注（`radius:0` 表示不画点）；`minZoom` 参与分级 |
| `annulus` 圈层 | `kind`（ring/bearing-ring/bearing-line/grid）、半径/方位/格数 | 几何在模块内计算为线要素 |
| `symbol` 标绘符号 | `symbol`、`affiliation`、`rotation`、`size` | 图标由模块逐像素栅格化后注册；框形与颜色随敌我属性变化 |

### 7.3 调色板（未显式给色时的缺省）

```
威胁   high 红 ｜ mid 琥珀 ｜ low 青
状态   red 红 ｜ yellow 琥珀 ｜ gray 灰
无人机 optical 青 ｜ radar 琥珀 ｜ electronic 紫 ｜ comm 绿
链路   green 绿 ｜ yellow 琥珀 ｜ red 红
其它   区域 青 ｜ 轨迹 红 ｜ 扫描 浅蓝 ｜ 脉冲 青 ｜ 集群 紫 ｜ 标注 浅灰蓝
```

**数据与样式解耦**：图元自带 `color/label/selected/…`；未给才用调色板。因此宿主换配色不需要改模块，模块换配色也不影响宿主数据。

### 7.4 公里 → 像素

```
kmToPixels(km, lat) = max(2, km*1000 / metersPerPixel)
metersPerPixel = 156543.03392 * cos(lat) / 2^zoom
```

扫描半径因此是**真实地理尺度**，且随缩放自适应（缩放钩子在有扫描图元时才注册，避免空转）。

集中一处、改一个值即生效：

| 开关 | 默认 | 说明 |
|---|---|---|
| `showAttribution` | `false` | 合规类开关；关闭时不写入署名文本 |
| `compactAttribution` | `true` | 署名紧凑模式 |
| `rasterFadeDuration` | `0` | 瓦片淡入时长 |

## 9. 交互层、扩展能力与回放

### 9.1 交互层（`ui/DrawLayer.tsx` + `core/interaction.ts` + `core/geometry.ts`）

| 能力 | 设计 |
|---|---|
| 绘制点/线/面 | 订阅地图事件收集顶点 → 用临时数据源做**预览**（不进图元集合）→ 结束时调 `MapDraw.add` 落库 |
| 测距/测面/方位角 | 复用同一套顶点收集；球面公式内联实现（haversine 距离、球面多边形面积），**不引第三方依赖** |
| 编辑 | 选中图元进入编辑态：顶点拖拽、插入/删除顶点、整体拖拽（顶点全选等价实现）；拖动过程只更新预览源，松手一次性写回 |
| 吸附 | 吸附到已有图元顶点；用屏幕像素距离判定，命中即替换坐标并给出提示 |
| 键盘 | 方向键平移、`+/-` 缩放、Esc 取消、Enter 完成、Backspace 退点；在 INPUT/TEXTAREA/SELECT 内不接管 |

**原则**：交互层只做"事件 → 坐标 → 调用绘制 API"，**不碰渲染层**。

### 9.2 态势增强能力

| 能力 | 设计 |
|---|---|
| 圈层图元 | 几何（距离环/方位线/方位圈/九宫格）在 `core/annulus.ts` 计算为线要素，复用折线渲染 |
| 目标聚合 | 按**屏幕像素**聚类（默认阈值可配），随缩放自然变化，无需维护分级阈值表；点击可钻取 |
| 标签避让与分级 | 避让用渲染内核内建碰撞检测；分级按逐图元 `minZoom`；另有全图数量上限策略 |
| 标绘符号库 | 符号图形在模块内**同步逐像素栅格化**为图像后注册进样式（不依赖图标字体与外部图片）；符号语义由宿主的代号决定；`registerSymbol()` 支持扩展 |
| 样式模板与主题 | 命名样式集中登记，图元引用名字（改模板即批量生效）；三套主题含底图参数与图元可读性，运行中切换且样式重建后自动重套 |
| 图层排序与透明度 | 分组级排序与整体透明度；透明度**保留图元自身语义**（相乘而非覆盖） |

### 9.3 回放（`core/replay.ts` + `ui/ReplayBar.tsx`）

```
宿主：采集与存储（数据库 / 文件 / 内存）——模块不参与
  ↓  loadReplay({ tracks: [{ id, points: [{ t, lng, lat, alt?, heading? }] }] })
模块：时间轴状态机（当前时刻、播放中/暂停、倍速、跟随模式）
  ↓  按当前时刻从各轨迹截取点集 → 写入对应图元类型 → 渲染
  ↓  时间轴 UI（模块内置，不依赖宿主组件库）
宿主：可查询状态、可订阅变化回调以联动自己的图表
```

| 关键点 | 做法 |
|---|---|
| 数据切片 | 轨迹点按时间升序；每帧二分查找定位当前索引，避免整段扫描 |
| 播放驱动 | 单一动画帧循环推进时间（`t += dt × speed`）；暂停即停循环，不空转 |
| 性能 | 只更新受影响的图元类型，不整表重绘；轨迹多时用批量提交 |
| 结束行为 | 到达末尾自动暂停并停在末帧；停止保留当前帧，清空才移除图元 |
| 不做的事 | 不负责数据采集、存储与持久化；不做时间轴之外的编辑 |

## 10. 性能与可靠性设计

| 主题 | 设计 |
|---|---|
| 增量更新 | 数据变更走 `source.setData()`，不重建 source/layer |
| 批量与合帧 | `MapDraw.batch(fn)`：批次内只改集合，退出时对受影响类型各提交一次；同帧多次更新只重绘一次 |
| 容量基线 | 以实测基线为门槛（单次提交、单点更新、帧率、堆占用），基线可复测刷新、可对比判劣化 |
| 资源上限 | 有界容器：每类图元条数上限（超出丢最旧）、每数据源瓦片缓存上限（按加入时间淘汰）、诊断错误上限；支持周期巡检与立即淘汰 |
| 大数据量降级 | 抽稀（超阈值等步长保留、始终保留首尾）、几何简化（容差按屏幕像素换算）、标签数量上限；**在渲染入口降级，不改动图元集合**，`list()`/`export()` 始终全量 |
| 错误边界 | 逐项校验与渲染容错：非法项跳过并计数，通过错误回调上报 `{ kind, id, reason }`，不让一条脏数据中断整类渲染 |
| 渲染时机可观测 | 统计写入次数与真正落到数据源的提交次数，批量合并效果可验证 |
| 瓦片源降级 | 基于瓦片请求结果统计判定（识别瓦片模板特征、不误计非瓦片请求）；失败达阈值降级、恢复后自动回升；降级状态可查询、可订阅 |
| 瓦片包校验 | 清单生成脚本 + 清单比对 + 抽样探测；清单缺失时降级为抽样状态并给出可读原因 |
| 多实例隔离 | 实例注册表 + 各子系统按实例持有状态；组件式用法天然独立，命令式用法经"当前实例"路由（详见 §12.3） |

## 11. 配置与地址外置（外部依赖登记）

### 11.1 登记格式

任何外部对象都必须按"**提供方 / 形态 / 缺失时行为**"三要素登记，且不得成为接入前置条件。

### 11.2 登记清单

| 外部对象 | 提供方 | 形态 | 缺失时行为 |
|---|---|---|---|
| 底图瓦片 | 宿主（自行托管或指向任意静态服务） | `{z}/{x}/{y}` 模板字符串（配置注入） | 回落纯色底，页面可打开、可交互 |

| 底图清单 | 宿主 | 底图描述对象数组（前端配置或宿主后端均可） | 回落"单底图"默认行为 |
| 业务数据 | 宿主 | `MapData` / 绘制 API 参数 | 按空数组/默认值处理，不报错 |
| 回放数据 | 宿主 | 带时间戳的轨迹点集 | 无回放数据时不显示时间轴 |
| 渲染内核与 UI 框架 | 包管理器 | `maplibre-gl` / `react` / `zustand` | 无法运行（属必需依赖，随包交付声明） |

### 11.3 配置外置要求（解耦硬性项）

| 项 | 要求 |
|---|---|
| 默认瓦片模板 | 模块内**不内置**任何具体服务地址；默认值为空/占位，未配置即纯色底 |
| 开发期瓦片目录 | 由环境变量提供（如 `MAP2D_TILES_DIR`），未设置时使用目录内默认位置并打印可读提示 |
| 可选联调代理 | 由**配置文件**提供，未配置则不启用；模块源码内不出现任何目标主机与端口 |
| 端口与主机 | 开发服务器端口、监听范围均为可配置项；文档中的访问地址一律以占位符表示 |
| 调试与自动化 | 文档中的浏览器路径、调试端口一律要求"按你的环境替换" |

## 附录 A 关键设计决策与取舍

| # | 决策 | 理由 | 代价 / 边界 |
|---|---|---|---|
| D1 | **数据经 props 注入，模块不取数** | 模块可脱离任何宿主与后端运行；宿主数据源可任意替换 | 宿主必须自行编写适配层 |
| D2 | **绘制 API 与渲染分离**（`MapDraw` ↔ `LayerManager`） | 宿主只见图元语义；渲染细节可整体替换 | 多一层集合管理与转换代码 |
| D3 | **图元增量更新**（`setData` 而非重建图层） | 动态图层高频更新不卡顿 | 样式表达受 GeoJSON 能力限制 |
| D4 | **实例注册表 + 当前实例语义** | 组件式用法天然独立；命令式 API 保持单实例兼容 | 模块级状态尚未完全按实例隔离（已登记） |
| D5 | **样式重建后重放图元** | `setStyle` 必然清空 source/layer，重放比"把图元塞进样式"更简单可控 | 重放是一次全量提交，图元量大时有一次性开销 |
| D6 | **缺口底色用深蓝灰、栅格不淡入** | 观感上"没有黑框"；淡入会在过渡期露出半透明底 | 极端情况下仍可能短暂出现底色 |
| D7 | **低清叠底层独立成层** | 拖动时任何新区域先有低清影像 | 低层级瓦片会被请求两次（浏览器缓存去重） |
| D8 | **二维锁定** | 方向恒定、避免操作中迷失方向 | 无法查看倾斜/旋转视角 |
| D9 | **开关集中**（`MAP_OPTIONS`） | 合规与观感类开关不散落各文件，交付后使用方可自行决定 | 需重建样式才能生效的开关不会热更新 |
| D10 | **只引入必要的运行时依赖** | 依赖面最小，便于整目录拷贝 | 模块状态与宿主状态是两套，需要显式同步 |
| D11 | **业务规则外置、只留通用缺省** | 模块保持"无内置业务"，任何宿主都能直接用 | 需要业务表现的宿主必须提供映射与清单 |
| D12 | **外部地址一律配置注入** | 模块不含任何具体服务依赖，可离线自证 | 开箱即为"无底图"状态，需宿主配置才有影像 |
