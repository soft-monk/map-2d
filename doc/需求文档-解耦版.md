## 0. 模块定位与解耦基准

### 0.1 一句话定位

`map-2d` 是一个**只做二维地图渲染与图元绘制**的基座模块：**宿主给数据、调接口，模块出图**。
模块不知道宿主是谁、做什么业务、数据从哪来、部署在哪里。

### 0.2 解耦基准（本版的判定前提）

| 编号 | 基准 | 含义 |
|---|---|---|
| B1 | **单向依赖** | 只允许 `宿主 → 模块`（宿主调用公开接口、注入配置与数据）；禁止出现事实上的 `模块 → 宿主`（模块读取宿主状态、内置宿主业务规则、依赖宿主服务或仓库结构） |
| B2 | **可离线自证** | 在"只有本模块目录、无宿主、无后端、无外网"的环境下，模块必须能编译、启动、出图、跑通验收 |
| B3 | **无内置业务** | 模块内不出现具体宿主业务的名词、枚举、规则、字段与地址 |
| B4 | **配置可替换** | 一切地址、端口、模板、路径、清单均可由宿主配置；缺失时有明确默认与降级行为 |
| B5 | **契约自带** | 对外类型、接口、错误约定全部在模块内定义，宿主结构兼容即可传入，不要求宿主引用模块类型或具备特定业务模型 |
| B6 | **外部依赖登记** | 确需提及的外部对象（第三方服务、宿主可选提供的清单等）必须按"提供方 / 形态 / 缺失时行为"三要素登记，且不得成为接入前置条件 |

### 0.3 边界（本版明确排除）

| 边界 | 内容 |
|---|---|
| 🚫 三维能力 | 地形、三维建筑、2D/3D 切换、楼层与室内 |
| 🚫 业务逻辑 | 业务流程与阶段规则、台账与评级、链路状态机、任务编排 |
| 🚫 数据获取与存储 | 业务数据的采集、持久化、回放数据的存储，一律由宿主负责 |
| 🚫 界面框架 | 导航、业务面板、状态栏、顶栏等宿主界面 |
| 🚫 宿主具体形态 | 不假设宿主的目录结构、构建工具、端口、后端接口、仓库地址与发布方式 |
| 🚫 瓦片工程 | 切图、抓取、打包、分发 |
| 🚫 在线底图适配 | 不内置任何在线底图源与坐标系偏移适配；底图数据一律本地化，地址由宿主配置 |

## 2. 验收准则

### 2.1 解耦验收（本版核心，必须在"只有本模块"的前提下执行）

1. **可离线自证**：在无宿主、无后端、无外网的机器上，按交付物清单拷贝 → `npm install` → 构建 → 启动 → 出图 → 走完功能验收台，全程无阻断（M2-MZ-06-03、M2-MZ-07-01、M2-MZ-04-04）。
2. **无业务名词**：全仓检索不出现任何具体宿主的项目名、系统代号、业务流程编号、场景名、单位名称、接口路径（M2-MZ-01-01、M2-MZ-01-06、M2-MZ-08-02）。
3. **无硬编码地址**：全仓检索不出现本机地址、端口、主仓目录名、外部仓库地址与发布脚本名（M2-MZ-05-01）。
4. **契约自足**：只传"配置 + 空数组"即可出图；所有业务上下文字段缺省均有定义行为（M2-MZ-02-01、M2-MZ-02-04）。
5. **实例独立**：两实例并行时数据、相机、主题、网格、图元集合互不影响；卸载一个不影响另一个（M2-MZ-03-01、M2-MZ-03-04、M2-NFR-08）。
6. **无全局副作用**：模块挂载与卸载前后，宿主的网络入口、DOM 结构、定时器状态完全一致（M2-MZ-04-01、M2-MZ-04-02、M2-MZ-03-02）。
7. **单一事实源**：状态数字、图元类数、分组数、导出清单各只有一处权威表述（M2-MZ-08-03、M2-MG-01）。
8. **自动守卫**：上述 1–7 中可脚本化的部分有对应自动检查，且默认通过（M2-MZ-07-02、M2-MG-01/02）。

### 2.2 功能验收

1. 模块独立宿主启动即出图（底图瓦片地址由配置指向；未配置时纯色底可交互）；
2. 漫游、缩放、二维锁定、视角命令按 M2-MAP 各条通过；
3. 默认不显示任何地图控件；逐个开启后四类控件与图例分别正确出现并可关闭，且互不遮挡；
4. 11 个图层分组可独立开关，状态跨底图切换保留；叠放次序与分组透明度可调；
5. 绘制接口覆盖 M2-DRAW-01 清单中的全部对象，且每个图元可单独显隐；
6. 手绘与编辑（M2-DRAW-08/12）在同一批交付内可用；量算实时显示结果且可清；
7. 回放：宿主加载带时间戳轨迹后，可用模块时间轴播放/暂停/倍速/拖动定位/自动跟随；
8. 多底图：声明两套本地底图后可任意互切且整体替换，切换后视角、图元、图层开关、控件开关全部保持，宿主收到通知；
9. 设定地面分辨率上限后，放大到更细层级不再请求新瓦片；该上限不影响在线样式底图。

### 2.3 接口验收

1. 宿主代码中不出现渲染内核的直接调用与模块内部路径；
2. 宿主传入的数据对象缺字段时不报错、按约定降级；
3. 导出/导入图元快照后画面一致；视图状态导出/恢复后画面一致，且导出内容不含宿主业务数据；
4. 第三方仅按"接口文档 + 接入指南 + 交付物清单"即可在自己的项目中跑起来，全程不离开本模块目录。

### 2.4 性能与可靠性验收

1. 复现基准脚本，各项耗时不超过基线；
2. 注入非法图元数据后，其余图元正常渲染；
3. 断开瓦片服务后地图仍可打开与交互。

### 2.5 交付验收

1. `npm run typecheck`、`npm run build` 通过；
2. 模块目录可直接拷贝到新项目运行；
3. 模块可独立成仓：clone 后 `npm install && npm run dev` 出图；
4. 交付前"无双仓自动检查"通过。

## 4. 建议执行顺序

| 批次 | 内容 | 理由 |
|---|---|---|
| 第一批 | M2-MZ-01（语义）、M2-MZ-02（契约）、M2-MZ-05（地址） | 决定对外契约形态，是所有后续工作的前提 |

**批次间依赖**：第一批 → 第二批（契约定了才能改实例模型）；第二批 → 第三批（行为定了才能定验收）；全部 → 第四批（文档与守卫必须描述已完成的事实）。
